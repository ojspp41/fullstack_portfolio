## 전체적인 아키텍처

![파일을 내려받지 않고 안전하게 미리보기 — 전체 구조](/diagrams/preview.png)

*구조 그림을 선택하면 원본 크기로 볼 수 있습니다.*

> **담당 범위:** FE 뷰어·Go 미리보기 API·권한 확인·현재 처리 세대 선택·스트리밍을 직접 구현했습니다. DRM 처리와 문서 PDF 변환 엔진은 기존 시스템 연동 범위입니다.

## 문제 원인 · 해결 목표 (S·T)

- **상황(S):** 파일 확인을 위해 다운로드가 필요했고, 요청마다 PDF를 변환·버퍼링하는 비용이 컸습니다. 덮어쓰기 후 이전 PDF가 남으면 오래된 내용을 보여줄 위험도 있었습니다.
- **목표(T):** 원본 다운로드와 처리 사본 미리보기를 분리하고, 현재 원본에 맞는 PDF만 제공하면서 요청당 처리·메모리 비용을 줄여야 했습니다.

## 해결 과정 (A)

1. 원본 다운로드와 DRM 처리 사본 미리보기의 API 경로를 나누고, 서버에서 파일 읽기 권한을 확인했습니다.
2. PPTX·HWP·HWPX는 파싱 과정에서 PDF를 선생성합니다. Gateway가 현재 파일 ID·`processing_attempt_id`로 객체 키를 선택하고 `%PDF` 접두부 확인 후 `io.Copy`로 스트리밍하도록 연결했습니다. 현재 세대가 처리 중이면 오래된 PDF로 폴백하지 않습니다. 완료된 구형 파일에만 배포 호환을 위한 기존 키 폴백을 제한적으로 허용합니다.
3. 프론트는 형식별 렌더링·정제·iframe 출처 격리를 적용했습니다. 요청 취소, Blob URL과 임시 자원 정리도 같은 생명주기로 묶었습니다.

## 결과 (R)

| 로컬 측정 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 10MiB PDF 내부 처리 | 1.59ms | 154.5µs |
| 요청당 누적 할당 | 49.84MiB | 229B |
| 동시 10개 최대 RSS | 740.4MiB | 53.2MiB |

전체 PDF를 메모리에 복사하는 대신 작은 버퍼로 바로 전달해 내부 처리와 메모리 부담을 줄였습니다. 현재 처리 세대의 PDF만 선택해 이전 세대 사본의 노출도 차단했습니다.

### 검증 조건 · 현재 한계

Apple M5·Go 1.24.5에서 같은 PDF 바이트로 경로별 3회 측정한 중앙값입니다. MinIO 네트워크·권한 조회·PDF 변환 시간은 제외했습니다. 사용자 전체 미리보기 시간이 10배 개선됐다는 뜻은 아닙니다.

프론트는 PDF 준비 중·변환 실패·네트워크 오류를 일반 미리보기 실패로 표시하며 자동 재시도를 제공하지 않습니다. 처리 상태별 안내는 남은 개선 범위입니다.
