## 전체적인 아키텍처

![SLP · MES 생산 리포팅 에이전트 — 전체 구조](/diagrams/slp.png)

*구조 그림을 선택하면 원본 크기로 볼 수 있습니다.*

> **담당 범위:** MES MCP의 목적별 조회 도구와 Agent 동작을 개발했습니다. 기존 MES·MS-SQL과 온프레미스 sLLM을 연동한 경험이며 모델 학습·MES 전체 구축과 구분합니다.

## 문제 원인 · 해결 목표

- **상황:** 생산 리포팅은 SQL 조회, Excel 취합, 문서 편집에 의존해 반복 작업이 많았습니다.
- **목표:** 자연어 요청에서 MES 조회·기간 비교·근거가 담긴 보고서 생성까지 연결하되, AI가 수치를 임의로 만들지 않도록 해야 했습니다.

## 해결 과정

1. 기간·라인·LOT를 입력받는 목적별 **읽기 전용 MCP 도구**를 연결했습니다. 임의 SQL 실행 대신 필요한 조회 범위를 제한했습니다.
2. 현재 기간과 직전 동일 기간을 비교하고, 이상 변동은 추가 조회했습니다. 도구가 반환한 사실과 AI 해석을 나눠 근거를 확인할 수 있게 했습니다.
3. 조회 결과를 화면 요약과 HTML 보고서로 연결했습니다. 도구 재시도, 결과 누락, 파일 생성 실패를 정상 흐름과 나눠 확인했습니다.

## 결과

- **생산·품질·설비·LOT 4개 영역**의 조회·비교·요약·HTML 보고서 생성 흐름을 연결했습니다.
- **5개 시나리오:** 성공 3건, 조건부 성공 1건, 인프라 차단 1건. 품질 개선점 5건을 도출했습니다.

### 검증 조건 · 현재 한계

인프라 장애로 막힌 검증과 Agent 자체 실패를 구분했습니다. 후속 재시험 항목 8개는 정의한 목록이며 모두 통과한 결과가 아닙니다. 현장 업무 시간 절감과 제조 품질 향상은 실측하지 않았습니다.
