# Generative UI 파이프라인

모델 출력을 믿을 수 없어, 깨진 JSON을 받아도 위젯이 뜨도록 클라이언트에서 복구하는 파이프라인입니다. 회복률을 코드로 측정해 회귀를 자동으로 잡습니다.

### 한 줄 요약

6단계 정제(sanitize) + 2단계 파싱으로 깨진 JSON을 복구합니다. 회복률은 40개 테스트 세트로 자동 측정하고, 규칙을 바꿔도 회귀가 즉시 잡힙니다.

### 핵심 지표

| 항목 | 결과 |
|---|---|
| JSON 회복률 | 60% → 97.5% |
| 복구 계층 | 2겹 파싱 — 1차 `JSON.parse` 실패 시 sanitize 후 2차 시도 |
| 회귀 방어 | 벤치마크 테스트 자동화 — 규칙 변경 시 깨짐 유형별 샘플 자동 재검사 |

### 다단계 복구 흐름(Pipeline)

정상이면 통과하고, 깨지면 ①~⑥ 순서로 복구합니다.

1. fence
2. 참거짓
3. 꼬리쉼표
4. 쉼표보강
5. 특수문자
6. 균형검사

| 번호 | 라벨 | 깨진 것 | 고친 것 |
|---:|---|---|---|
| ① | fence | ````json {…} ```` | `{…}` |
| ② | 참거짓 | `true"` | `true` |
| ③ | 꼬리쉼표 | `["a",]` | `["a"]` |
| ④ | 쉼표보강 | `}{` | `},{` |
| ⑤ | 특수문자 | `"줄 ⏎ 바꿈"` | `"줄 \n 바꿈"` |
| ⑥ | 균형검사 | `{"a":[1,2}` | 거부 |

### 왜 이 순서인가 — 정제 먼저, 검사 나중

**문제**
⑥ 괄호 균형검사를 정제 앞에 두니, 따옴표가 깨진 JSON(`true"`)을 복구도 못 해보고 버렸습니다.

**원인**
깨진 따옴표가 “문자열 안/밖” 판단을 어긋나게 해 괄호 개수가 틀어집니다.

**해결**
②~⑤로 문자를 먼저 정상화한 뒤 ⑥에서 검사하도록 순서를 바꿨습니다. 회귀 방지용 fixture 테스트로 고정했습니다.

# 위젯 격리 — 깨져도 채팅은 살리기

### 사고 과정 — 어떻게 알아냈나

- **문제 정의**: 잘못된 데이터로 위젯을 렌더링하자, 채팅 화면 전체가 언마운트되고 누적 대화까지 사라졌습니다.
- **가설**: Error Boundary가 없으면 React가 트리 전체를 언마운트하므로, 위젯 예외가 채팅까지 끌고 내려간다고 봤습니다.
- **검증**: 일부러 깨뜨린 fixture(괄호 불균형 JSON)를 주입해 재현했습니다. Boundary가 없는 버전은 세션 전체가 소실됐고, 위젯 단위 Boundary를 넣자 위젯만 fallback으로 처리됐습니다.

### 해결 1 — 위젯마다 안전망 두르기

위젯마다 안전망(`GenUIErrorBoundary`)을 둘렀습니다. 깨져도 그 자리에만 “위젯을 표시할 수 없습니다” 대체 메시지가 뜨고, 채팅은 그대로 유지됩니다.

```tsx
<GenUIErrorBoundary>
  <CardSelectionWidget ... />
</GenUIErrorBoundary>
```

### 해결 2 — 이벤트 버스로 분리: Context 대신 pub/sub

React Context로 전달하면 `value`가 바뀔 때마다 채팅 메시지 N개가 전부 리렌더돼 비용이 컸습니다. 전역 이벤트 버스(pub/sub)로 바꿔 상호작용이 React 트리를 거치지 않게 했습니다.

- 무관한 메시지 리렌더 0
- 이벤트명 오타는 `EventMap` 타입으로 방지
- 구독 해제 누락은 `useBusEvent(cleanup)` 훅으로 방지

```ts
eventBus.emit('genui:interact', payload)
eventBus.on('genui:interact', handler)
```

### 회고 — 한계 발견과 재발 방지

검증 과정에서 Error Boundary가 비동기·핸들러 예외는 잡지 못한다는 한계를 발견해 `try/catch` 수렴 로직을 추가했습니다. 이후 같은 깨짐 패턴은 회귀 벤치가 자동으로 잡습니다.

### 스트리밍 중 깜빡임 제거 — skeleton / dots UX 타이밍

위젯 JSON은 한 토큰씩 흘러들어오는 동안 계속 미완성 상태입니다. 도착하는 즉시 그리면 반쪽짜리 위젯이 마운트·언마운트를 반복해 화면이 깜빡입니다.

따라서 스트리밍 구간에는 위젯을 그리지 않고 skeleton과 typing-dots로 자리만 잡았다가, 파이프라인이 완전한 JSON을 통과시킨 순간 한 번에 실제 위젯으로 바꿨습니다.

- 스트리밍 중 → skeleton · dots
- 깨짐 → fallback
- 완성 → 실제 위젯

스트리밍·깨짐·완성 세 상태를 분리해 사용자가 보는 첫 화면을 안정화했습니다.

### 측정 결과

`genui-parse.bench` 실측(sanitize 전후)

| 지표 | 결과 |
|---|---|
| 파싱 성공률 | 60% → 97.5% |
| 파싱 실패 payload | 16건 → 1건 |
| 파싱 실패 | 약 94%↓ |

40개 fixture 기준으로 sanitize 적용 전 16건이던 파싱 실패를 1건으로 줄여 실패율을 약 94% 낮췄습니다. fixture는 코드블록 감싸짐·Bool 따옴표·후행 쉼표·괄호 불균형·복합 깨짐 유형으로 구성해 `genui-parse.bench`에서 측정했습니다. 파싱을 통과한 뒤 발생하는 렌더 예외는 Error Boundary로 격리해, 위젯 1개 장애의 영향 범위를 세션 전체(메시지 N개 + 입력 컨텍스트)에서 해당 위젯 1개로 축소했습니다.
