## 전체적인 아키텍처

![WebSocket 연결·스트리밍 화면 안정화 — 전체 구조](/diagrams/websocket.png)

*구조 그림을 선택하면 원본 크기로 볼 수 있습니다.*

> **담당 범위:** 클라이언트 연결 생명주기·세션 상태·응답 반영을 구현했습니다. 서버 전송 프로토콜 전체를 바꾼 경험과 구분합니다.

## 문제 원인 · 해결 목표

- **상황:** 중복 연결, 이전 소켓의 이벤트, 숨김 탭 종료로 응답이 끊겼습니다. 청크마다 화면을 갱신하면 폭주 시 렌더링 부담도 커졌습니다.
- **목표:** 중복 송신과 스트리밍 손실을 막고, 정상 속도의 응답을 유지하면서 폭주 패턴의 불필요한 화면 갱신을 줄여야 했습니다.

## 해결 과정

1. Heartbeat, 지수 백오프와 Jitter를 적용하고, 연결 가드와 세대 확인으로 중복 연결·이전 소켓 이벤트를 차단했습니다. 인증 실패에는 재연결을 중단했습니다.
2. 숨김 탭은 **5분 뒤 유휴 연결만 종료**하고 스트리밍 중에는 유지했습니다. 활성 세션 설정의 중복 송신도 막았습니다.
3. 짧은 3ms 구간으로 청크를 묶어 반영하고 마지막 응답은 누락 없이 반영했습니다. 폭주·혼합·정상 패턴을 따로 측정했습니다.

## 결과

| React Profiler 입력 패턴 | 변경 전 | 변경 후 |
|---|---|---|
| 폭주 · 500개 청크 | 500회 | 2회 · 99.6% 감소 |
| 혼합 패턴 | 200회 | 100회 |
| 정상 패턴 | 60회 | 60회 |

### 검증 조건 · 현재 한계

99.6%는 고정 폭주 패턴의 React Profiler 화면 갱신 횟수입니다. 정상 패턴은 같은 횟수를 유지했고, 네트워크 지연·사용자 체감 시간·전체 서비스 처리량을 측정한 결과는 아닙니다.
