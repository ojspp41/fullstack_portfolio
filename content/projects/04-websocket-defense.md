# 실시간 통신 6단계 방어(WebSocket)

**AI 응답이 끊기지 않는 실시간 채팅 만들기**

### 프로젝트 배경

사내 AI 챗봇(LLM)을 여러 조직·여러 세션 환경으로 넓히면서 수십 초씩 이어지는 응답에서 세 가지 문제가 반복됐습니다.

- 응답 섞임
- 백그라운드 탭 끊김
- 응답이 몰릴 때 화면 버벅임

서버는 그대로 두고 클라이언트(브라우저) 쪽에 6단계 방어 구조를 설계·구현했습니다.

### 핵심 성과

| 조건 | 지표 | 결과 |
|---|---|---:|
| 극단 폭주 · 1ms 간격 | 리렌더링 횟수 감소 | 99.6% |
| 실사용 패턴 | 화면 갱신 횟수 감소 | 50.0% |
| 정상 응답 | 화면 갱신 횟수 변화 | 0% |

### 6단계 방어 구조

#### 1. 연결 상태 신호(Heartbeat)

30초마다 신호를 주고받으며 연결이 살아 있는지 확인합니다. 응답이 없으면 끊긴 것으로 보고 즉시 다시 연결합니다.

#### 2. 지수 백오프 + 지터(Backoff + Jitter)

재연결 간격을 1초 → 2초 → 4초 → 8초 → 16초로 늘리고, 무작위 지터를 더해 간격을 흩뜨립니다. 끊긴 사용자들이 같은 시점에 한꺼번에 몰려와 서버가 다시 멈추는 사태를 막습니다.

#### 3. 중복 연결 차단

같은 사용자에게 연결이 두 번 열리지 않도록 3단계로 막습니다.

- 중복 감지
- 소유권 잠금
- 인증키 검증

#### 4. 탭 상태 인식(Page Visibility)

탭이 숨겨져도 5분 동안 연결을 유지하고, 응답 생성 중이라면 시간이 지나도 연결을 끊지 않습니다. 5분이 지난 유휴 연결만 종료하며, 다시 화면으로 돌아오면 즉시 재연결합니다.

#### 5. 인증키 자동 갱신(Token Refresh)

인증키 만료를 감지하면 자동으로 새 키를 받아 끊김 없이 다시 연결합니다.

#### 6. 종료 코드별 처리

종료 코드에 따라 다르게 대응합니다.

- 1000: 정상 종료
- 1006: 네트워크 단절
- 1011: 서버 오류
- 4001: 정책 위반(재로그인)

# 응답이 섞이는 문제(Race Condition)

### 문제 → 시도 → 해결 흐름

1. 사용자가 새 LLM 세션 시작
2. 응답 도중 이전 요청이 뒤늦게 도착해 글자가 섞이는 문제 발생
3. 시도 1 — 실패
   - 요청을 취소(`abort`)해도 이미 도착한 응답은 계속 들어옴
4. 시도 2 — 실패
   - 상태(`state`)로 비교하니 옛 값을 참조하는 문제(stale closure) 발생
5. 최종 해결
   - `useRef`로 현재 세션 ID 추적
   - 들어오는 응답마다 비교 후 폐기

## 화면 갱신 묶음 처리(Batching) — 3ms debounce

응답 조각이 몰려서 도착할 때 매번 화면을 다시 그리면 갱신이 쌓입니다. 3ms 동안 입력을 모았다가 한 번에 갱신(Debounce)으로 압축합니다.

| 도착 패턴 | 설명 | 조각 수 | 개선 전 | 개선 후 | 감소율 |
|---|---|---:|---:|---:|---:|
| 버스트(약 1ms 간격) | 네트워크 정체 해제 직후 | 500 | 500 | 2 | 99.6% |
| 혼합 | 정상 → 버스트 → 정상 | 200 | 200 | 100 | 50.0% |
| 정상 30조각/초 | 의도된 무변화 | 60 | 60 | 60 | 0% |

### 측정 방식

React `<Profiler>`의 `onRender` 콜백으로 화면 갱신(커밋) 횟수를 집계했습니다. 도착 타임스탬프를 고정한 동일 입력을 debounce 적용 전·후로 각각 replay해 비교했습니다.

### 핵심 인사이트

정상 응답에서는 조각 간격이 3ms보다 커서 묶음 처리가 작동하지 않습니다. 몰릴 때만 묶고, 정상일 때는 그대로 통과시키도록 의도한 설계입니다.

### 결과 및 학습

- 응답이 섞이는 현상 해소
- 백그라운드 탭 복귀 시 끊김 제거
- 응답 몰림 시 화면 버벅임 제거
- React가 오래된 값을 기억하는 한계(stale closure)를 이해
- 상태를 React 바깥(`useRef`)으로 분리하는 방법 학습
